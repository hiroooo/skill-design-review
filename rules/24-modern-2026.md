# 「2026 年 確実に古い」10 連発

これが見つかったら問答無用で priority `high` か `medium`。レポート冒頭の警告枠に出す。

## 1. Comic Sans / Papyrus / Impact 直使い
- 30 年変わらない「素人」記号
- → `high`

## 2. 完全黒 (`#000000`) / 完全白 (`#ffffff`) のみ
- 2026 では gray-900 / gray-50 の方が標準
- → `medium`

## 3. 線形 easing (linear) 多用
- アニメーションが物理的に不自然
- → `medium`、cubic-bezier 推奨

## 4. mobile で max-width 未設定 (margin: 0 端張り付き)
- 2026 は max-width: min(90vw, 1200px) が標準
- → `high`

## 5. グラデーションボタン (top→bottom 白→灰)
- 2000 年代 Web style、Bootstrap 2 系
- 2026 は flat button + subtle shadow
- → `high`

## 6. font-weight 1-2 種だけ
- 階層感ゼロ、フラットすぎる
- 2026 は variable font で 4-6 段階 weight が普通
- → `medium`

## 7. border-radius 4 種以上混在
- design token 不在の証拠
- 2026 は 2-3 種で統一
- → `medium`

## 8. section margin 全部同じ (リズム破壊)
- 階層感ゼロ、流し読みできない
- 2026 は 64/96/128px のような階層的 rhythm
- → `medium`

## 9. hero に visual なし (文字だけ)
- 2026 SaaS LP の標準は「hero に視覚」
- Apple / Vercel / Stripe / Linear / Figma すべて hero img あり
- → `medium` (Editorial 狙いなら friendly)

## 10. box-shadow opacity > 0.5 + blur < 10
- ハードな黒 shadow、2010 年代 Material Design v1 風
- 2026 は rgba(0,0,0,0.05-0.12) の極薄
- → `low` (頻発なら medium に格上げ)

## ボーナス: 2026 年「これは新しい」シグナル

逆に **見つけたら積極的に褒める** 良い点:

1. **variable font** (`font-variation-settings`) 使用
2. **container queries** (`@container`) でレスポンシブ
3. **CSS color-mix()** / `oklch()` 系 wide gamut
4. **subtle gradient mesh** (Vercel / Stripe 風)
5. **scroll-driven animation** (`animation-timeline: scroll()`)
6. **view-transition** API
7. **iOS Liquid Glass** 風 (`.ultraThinMaterial`, depth layering)
8. **dynamic color** (Material You) on Android
9. **Inter / Geist / Pretendard / Söhne** などの 2026 スタンダード
10. **subtle micro-interaction** (haptic feedback, springy scroll)

## 11. Anthropic 公式 frontend-design plugin 由来の「AI 生成の型」(2026-09-18 追加、2026-09-19 複合判定に改訂)

Claude 自身が生成するデザインが収束しやすいと Anthropic 公式 (claude-plugins-official/frontend-design) が認めている型。1-10 と重複しないものだけを追加する。

**複合判定の考え方**: 11a〜11f はどれも単独では「よくある選択」の範囲に収まりうる (例: 11f の準黒はそれ単独では rule 23 S1 / RC-08 が推奨する正しい実装)。Anthropic 公式が指摘しているのは、これらが**セットで揃ったときにテンプレ臭くなる**ことであって、個々の要素を単独で禁じているわけではない。そのため:

- 11a〜11e の各シグナルは、**単独成立では `low`** (指摘のみ、実装を止めない)
- 同一対象で **2 つ以上のシグナルが同時に成立したら、まとめて 1 件の `high` issue に格上げ**する (「AI 生成の型に複数該当」)
- 11f (準黒) は**単独では一切 issue 化しない**。11a〜11e のうちすでに 2 つ以上成立しているときに限り、3 つ目以降のシグナルとして数える

### 11a. 暖色クリーム + セリフ + テラコッタ

- 背景が暖色クリーム (`#F4F1EA` 近傍) + ハイコントラストのセリフ見出し + テラコッタ系アクセント (`#D97757` 近傍) の組み合わせ
- `#D97757` は Anthropic 自身の Claude UI アクセント色そのもの。使うと逆に「AI が作った」と即バレる
- → 単独: `low`。複合成立時は `high` (下記「複合判定の実装」参照)

```js
// getComputedStyle は rgb(...) 文字列で返る。RGB 距離で近似一致を判定 (完全一致でなく ±15 程度の近傍も拾う)
const rgbDist = (a,b) => Math.sqrt(a.reduce((s,v,i)=>s+(v-b[i])**2,0));
const parseRgb = s => { const m = s.match(/rgba?\((\d+),\s*(\d+),\s*(\d+)/); return m ? [+m[1],+m[2],+m[3]] : null; };
const TERRACOTTA = [217, 119, 87]; // #D97757 (Anthropic 自身の Claude アクセント色)
const CREAM = [244, 241, 234];     // #F4F1EA
const sig_terracotta = styles.colors.some(c => { const rgb = parseRgb(c); return rgb && rgbDist(rgb, TERRACOTTA) < 15; });
```

### 11b. ほぼ黒背景 + 単色ビビッドアクセントのみ

- 背景がほぼ黒 (`#0a0a0a`〜`#161616` 帯) で、アクセントが蛍光グリーン or 朱色 1 色だけという構図
- rule 23 S1 (true black 禁止) とは別軸: こちらは色そのものでなく「ほぼ黒背景 + ビビッドアクセント 1 色」という**構図パターン**自体を問題にする
- → 単独: `low`。複合成立時は `high`

### 11c. ブロードシート新聞調

- ヘアラインルール (1px border) の多用 + `border-radius: 0` + 新聞コラム風の密な段組み
- → 単独: `low`。複合成立時は `high` (新聞・メディア系ブランドで意図的な場合は対象外)

### 11d. カードの視覚的階層を無視した均一装飾

- 重要度が異なるカード群 (例: 通常カード vs highlight カード) に、border-radius・box-shadow・グラデーション装飾が**全く同じ値で機械的に適用**されている
- rule 23 S11「全部同じ radius」は単体では `low` (悪くない) 判定のままで変更しない。ここで問題にするのは**階層が異なるはずの要素にまで無差別適用**されている状態だけ。shadow の絶対値 (rgba(0,0,0,0.05-0.12) 自体は rule 23 の良い点ハイライト通り推奨レンジのままで問題ない — 値でなく「差別化ゼロ」を検出する)
- → 単独: `low`。複合成立時は `high`

### 11e. テンプレ的装飾記号の機械的多用 (grep 可能)

```js
const links = [...document.querySelectorAll('a, button')];
const arrowTrailRate = links.filter(el => /→\s*$/.test(el.textContent.trim())).length / (links.length || 1);
const sig_arrowTrail = arrowTrailRate > 0.5;

const bodyText = document.body.innerText;
const interpunctCount = (bodyText.match(/·/g) || []).length;
const sig_interpunct = interpunctCount >= 3;

const emdashLabelCount = (bodyText.match(/[A-Za-z0-9]+\s+—\s+\S+/g) || []).length;
const sig_emdashLabel = emdashLabelCount >= 3;

const headings = [...document.querySelectorAll('h1,h2,h3')];
const sig_eyebrowAllcaps = headings.length > 0 && headings.every(h => {
  const prev = h.previousElementSibling;
  return prev && getComputedStyle(prev).textTransform === 'uppercase';
});
```

- リンク/ボタン文末の `→` 一律付与 → 単独: `low`。複合成立時は `high`
- 中点 `·` 区切りのメタ文字列多用 → 単独: `low`。複合成立時は `high`
- em dash 付きラベル `"WORD — fragment"` の統一多用 → 単独: `low`。複合成立時は `high`
- 見出し全部に tracked-out ALL CAPS eyebrow ラベルが内容の種類に関わらず一律で付いている → 単独: `low`。複合成立時は `high`

### 11f. 準黒 (`#0B0B0B` / `#111` 近傍) — 単独では検出しない補助シグナル

- 公式 frontend-design は準黒を「真の黒の代用として使われるテンプレ感」の tell として挙げているが、本ファイルの rule 23 S1 と `rules/45-recurrence.md` RC-08 は `#111111` を true black 回避の**推奨代替**として明示している。この2つは矛盾しない: **準黒それ自体は正しい実装**であり、単独で違反にはしない
- Anthropic 公式が指しているのは「準黒 **も含めて** 11a〜11e の型が複数そろったときのテンプレ感」であって、準黒単独ではない。そのため 11f は**単独では issue化しない** — 11a〜11e がすでに 2 つ以上成立しているときに限り、3 つ目以降のシグナルとして複合判定に加える

```js
const NEARBLACK = [11, 11, 11]; // #0B0B0B
const sig_nearBlackShade = styles.colors.some(c => { const rgb = parseRgb(c); return rgb && rgbDist(rgb, NEARBLACK) < 15; });
```

### 複合判定の実装

```js
// 11a〜11f の各シグナル (boolean) を集計する。
// 11f (準黒) だけは単独では計上しない — 他が2つ以上成立して初めてカウントに入る。
const primarySignals = {
  terracotta: sig_terracotta,
  nearBlackVivid: /* 11b の判定結果 */ false,
  broadsheet: /* 11c の判定結果 */ false,
  uniformCardDeco: /* 11d の判定結果 */ false,
  arrowTrail: sig_arrowTrail,
  interpunct: sig_interpunct,
  emdashLabel: sig_emdashLabel,
  eyebrowAllcaps: sig_eyebrowAllcaps,
};
const activePrimary = Object.entries(primarySignals).filter(([, v]) => v).map(([k]) => k);

if (activePrimary.length >= 2) {
  const names = sig_nearBlackShade ? [...activePrimary, 'nearBlackShade'] : activePrimary;
  issue('ai_tell_compound', 'high', `AI 生成の型に複数該当 (${names.length} 件: ${names.join(', ')})`);
} else {
  // 単独成立のみ: low で個別に出す。11f は totalActive < 2 のときは一切出さない。
  activePrimary.forEach(k => issue(`ai_tell_${k}`, 'low', `AI 生成の型シグナルを 1 件検出: ${k} (単独成立、複合ではない)`));
}
```
